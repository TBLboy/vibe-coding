# Project Rules

Use this file for project-specific business rules, architecture constraints, test commands, and safety requirements. Keep it short and authoritative.

## Required

- Preserve explicit product behavior and acceptance criteria.
- Prefer the smallest coherent change that satisfies the request.
- Run the relevant verification for the changed behavior and report results honestly.
- Ask the user when an unresolved business decision materially changes product behavior.
- Do not expand scope or add speculative features.

## Project-specific facts

- Add only rules that are stable, actionable, and not already obvious from the code or tests.
