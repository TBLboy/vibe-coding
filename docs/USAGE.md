# Vibe Coding 使用指南

## 适用客户端

Vibe Coding 框架面向 Codex 的四种接入端一致生效：

- Codex CLI
- VS Code 插件
- 桌面端
- ACP 外部协议连接端

无论使用哪种客户端连接，用户级全局规则、Skills、`.project-log/` 生命周期、Hooks 与归档链路都相同，不因接入端不同而行为漂移。

## 一个真实任务：给机器人项目新增设备状态采集

以团队协作的机器人项目为例：类似 ROS 2 工作空间，包含主线仓库与独立执行器仓库，同一分支多人开发，修改公共资源需先征得同意。本次任务：为系统新增「设备状态采集」功能。

### 第一步：初始化工程

在项目根目录对 agent 说：

> 初始化工程

agent 会执行：

1. 检查目录的 Git 状态：没有仓库时先询问是否需要 `git init`；已有仓库时询问是个人仓库还是团队协作仓库。
2. 生成 `.project-log/`：包含需求、业务逻辑、架构、任务、决策、验证证据等全套工程记录骨架。
3. 建立或安全更新根目录 `AGENTS.md`：注入通用开发规则，并留出「项目级规则」区。
4. 把项目开发注意事项写入 `AGENTS.md` 项目级规则区，例如：修改公共接口前必须询问；执行器仓库改动单独提交；个人环境问题不上升为团队配置。

之后每次对话 agent 都会自动读取该 `AGENTS.md`，遵守项目约束。

### 第二步：业务逻辑澄清

> 进入业务逻辑澄清阶段

与 agent 交流，把任务讲清楚。agent 会从三个维度对齐：

- **功能业务逻辑**：采集哪些设备、采集频率、异常如何处理、数据流向哪里、边界条件是什么。
- **技术业务逻辑**：现有系统如何承载——现有消息/接口、节点、数据流、已有配置。
- **双向对齐**：比较「应该怎样」与「实际怎样」，找出匹配、缺失与冲突。

示例：澄清中发现现有设备状态消息缺少业务要求的字段。这个问题会在澄清阶段被明确记录，而不是等到写代码时才暴露。

### 第三步：技术选型

> 进入技术选型

结合现有资源决定具体技术层面：

- 用什么接口：新增自定义消息，还是复用现有 topic/服务。
- 用什么架构：采集逻辑放现有节点，还是新增节点；是否必须改动公共接口。
- 兼容约束：是否影响同一分支其他同事的开发。

决策会记录到 `.project-log/decisions/`，写明选择理由，后续可追溯、可质疑。

### 第四步：代码落地

> 进入代码落地

agent 自动把任务拆解成可验证的小任务，按闭环推进：

```text
写代码 → 测试 → 收集证据 → 判断是否通过
```

- 每个任务都有明确的完成条件（done_when）。
- 实现完成后不是口头声称完成，而是给出测试命令与结果作为证据。
- 任务状态、业务逻辑、遇到的问题、开发进度和经历，全部写入 `.project-log/`。

### 第五步：链路不是线性的

遇到 BUG 或发现需求理解有偏差时，可以直接回到之前的环节：

> 测试发现采集时序不满足业务要求，回到业务逻辑澄清重新对齐

agent 会从澄清阶段重新走，而不是在代码层硬打补丁。整个生命周期是可回退的证据链：

```text
业务逻辑澄清 → 技术选型 → 代码落地 → 验证 → 复盘
```

任意环节发现问题都可以回退到对应环节。

### 第六步：归档工程

开发完成（或阶段完成）后说：

> 帮我归档这个工程

agent 会调用归档 Skills（`a-project-log-archive`）：

1. 使用你设置好的个人知识库（如 `My_knowledge_base`）作为归档目标。
2. 把当前项目的 `.project-log/` 归档到知识库对应目录。
3. 自动提交并推送到知识库的 Git 远端。

这样项目经历全程留痕，后续可以做个人分析、复盘和经验蒸馏，不丢失过程。

## Skills 分级

框架内置 Skills 分为两级：

- **a 级（通用 Skills）**：跨项目通用的流程能力，如项目初始化、业务澄清、技术选型、代码落地、验证、复盘、归档。
- **b 级（领域专业 Skills）**：特定领域的专业能力，如机器人部署、UX 审计、知识蒸馏等。

注册新 Skills 时，只需描述想要的技能，agent 会自动：

1. 判断它是通用技能还是领域技能，并完成分级。
2. 配置触发条件与路由，保证后续对话中自动调用。

## 框架特点

- **内外双循环**：内循环（恢复 → 执行 → 证据 → 失败归因 → 决策）保证每个工作单元闭环；外循环（业务澄清 → 技术选型 → 落地 → 验证 → 复盘）保证整个项目可回退、可追溯。
- **全程留痕**：`.project-log/` 记录业务逻辑、需求基线、决策、任务、验证证据与进度，不依赖聊天上下文。
- **证据驱动**：没有验证证据不声称完成，避免「好像做完了」。
- **决策分级**：低风险直接执行，影响业务语义的变更先询问并给出推荐答案。
- **团队友好**：遵守 `AGENTS.md` 中的项目约束，公共资源改动先征求同意，避免污染多人协作的公共仓库。
