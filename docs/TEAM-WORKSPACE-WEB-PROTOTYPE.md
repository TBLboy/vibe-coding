## 2. 产品边界

网页帮助团队**建立工作空间、完成成员加入、查看共享工程记录**。开发继续在本地 Git 和 OpenCode；网页不操作仓库，不检查本地目录里的仓库或分支，不加接入二次确认。

| 角色 | 在网页做什么 |
|---|---|
| 已登录账号 | 查看自己的工作空间与待处理邀请/申请；接受邀请或按已知空间 ID 申请；创建空间后成为该空间的负责人。负责人是空间内角色，不是全站账号类型。 |
| 已加入的成员 | 看概览、团队任务和工程日志，以及 OpenCode 接入说明。 |
| 工作空间负责人 | 成员能力 + 邀请、同意或拒绝加入申请。 |
| 待加入账号 | 只看自己邀请或申请的必要信息；不能看空间内部数据。 |

**明确不做**：网页创建、领取、改状态或拖拽团队任务；展示或同步 Vibe 本地个人 Task；代码/Git 操作、文档编辑、提案、实时推送、仪表大屏、真实服务调用。真实注册、成员移除、轮换 key 等不纳入这版可体验主流程。演示账号切换与清空演示数据不是生产功能。

## 3. 页面与信息层级

| 页面 | 内容和操作 |
|---|---|
| **登录** | 一张居中表单：邮箱、密码、登录。单独标「演示模式」，提供「使用负责人演示账号」「使用成员演示账号」，不要求输入任何真实凭据。 |
| **工作空间列表** | 显示已加入空间的名称和角色；单独显示待处理邀请、申请进度。一级动作「创建工作空间」，次级动作「申请加入」。只有已加入的空间可进入。 |
| **概览（默认页）** | 空间名称和「连接 OpenCode」；纵向排列成员进展、按状态分组的只读任务行、最近变更。成员行显示姓名、角色、最近活跃和可选当前团队任务；任务的标题/范围、持有者、更新时间对齐，保留放弃原因，不用四列卡片暗示拖拽。变更默认最新 5 条，可展开其余记录，不以长时间线撑出主内容空白。 |
| **工程日志** | 一个浅色文件浏览/阅读工作区：左侧采用类似 VS Code 的纯文字文件树，根目录为 `constitution / specs / work / members / activity`（中文含义在说明里），按真实路径逐层缩进，文件夹可折叠，仅显示文件夹与文件名，无文件/文件夹图标或重复标题；空分类保留。选中文件高亮，深链接自动展开父目录，其他折叠状态在当前页面内保持。右侧为路径、只读/版本/更新信息及安全正文。不执行文档里的 HTML/脚本。变更指向存在且可读的文件时可跳转；删除记录不提供死链接。 |
| **成员与接入** | 上方为完整成员管理区域，下方为独立全宽接入指南，不再把长命令挤入侧栏。成员列表将姓名与邮箱合并，保留角色和最近活跃；窄屏元数据换行。负责人额外看到邀请表单、等待接受的邀请，有申请时在成员列表前显示「通过 / 拒绝」；无申请只显示简短提示，不占独立面板。参考仓库默认折叠，仍仅供浏览、不参与接入。不新增管理功能或设置页。 |

```text
演示模式  ·  工作空间 / 支付项目                         当前账号 [退出]
支付项目                                             [连接 OpenCode]
[ 概览 ]   [ 工程日志 ]   [ 成员与接入 ]
团队成员与进展     林舟 · 成员 · 最近活跃 10:40    支付回调联调
团队任务（只读）   进行中 / 待领取 / 完成 / 放弃  [纵向分组列表]
最近变更          谁 / 做了什么 / 文件路径 / 时间  [默认5条，可展开]
```

**展示语义**：最近活跃来自模拟的 `lastSeenAt`，不是设备在线、Agent 正在工作或工时监控。最近变更是「谁、何时、对什么做了什么」；这样的元数据不是文件正文。任务用当前系统状态，不用个人 Task 或进度文件猜测任务状态；「待领取」只是标签，不是操作邀请。

## 4. 视觉资源约定

桌面优先、浅色、信息清晰。桌面内容居中，建议最大宽 `1200px`。按用户 2026-11-24 视觉反馈，概览不再使用 `2:1` 成员/变更共同行高布局，改为独立纵向区块，避免长变更撑出空白；窄屏任务元数据自然换行。日志宽屏目录约 `280px`、正文弹性布局，以细分隔线划分而非两张浮动卡片；窄屏目录整体折叠但可通过 Tab、Enter/Space 展开，再访问文件链接。不强制实现暗色或专门的移动端布局。

| 项 | 初版取值/行为 |
|---|---|
| 色板 | 画布 `#F6F7F9`、面板 `#FFFFFF`、边框 `#E2E8F0`、正文 `#172033`、次文字 `#475569`、强调 `#1D4ED8`。成功 `#166534`、待处理 `#92400E`、错误 `#B91C1C`，搭配文字标签。 |
| 字体与间距 | 系统字体与系统中文字体，不下载字库。正文 `14–16px`、区块标题 `18px`、页标题 `24–28px`；4/8/12/16/24/32 间距；边框和 8px 左右圆角，不做重阴影。 |
| 组件 | 顶栏、标签导航、页面区块、按钮、输入与字段级错误、状态标签、成员列表、变更列表、空状态、异步提示、简单对话框/面板。操作应可键盘触达，焦点明显；弹层关闭回到触发按钮。 |
| 资产 | 文本字标；初版用首字作为头像；可用少量本地单色线性图标（返回、复制、文件夹、文件、加号），图标不代替关键文字。不需要品牌包、插画、外链图标、图库、动画或生成图。 |

## 5. 关键交互和模拟状态

**负责人路径**：登录 →「创建工作空间」→ 填名称、提交 → 新空间立即出现在列表，当前账号为该空间负责人 →「成员与接入」邀请指定演示邮箱或处理待审批申请。表单和导航不为每个操作新增页面。

- **创建表单**：原型提案为「空间名称必填；仓库链接可选、可多填，仅供浏览」；不展示分支输入。此为 Mock 中要体验的取舍，不是已批准的后端 BR-2 修改；现有创建 API 仍要求至少一组仓库地址和分支。不得在未来接真接口时悄悄填 `main` 或忽略这个差异。
- **邀请**：输入邮箱 → 显示已邀请，匹配演示账号看见邀请；不会因发出邀请立即成为成员。不宣称发送真实邮件。
- **审批**：待审批项有通过/拒绝两个操作，执行期间禁用重复提交；成功后移出待审批。失败保留原状态、提供重试。拒绝后成员能看到未通过提示，仍不能进空间；不把拒绝当成删除记录。

**成员路径**：登录 → 接受与本人邮箱匹配的邀请，或输入已知工作空间 ID 申请 → 申请保持待审批，切换到负责人通过后，切回成员即可进入 → 看概览、日志和接入说明。接受邀请与申请审批是两条路径，不重复要求两步。重复请求显示已有状态，不增出第二条待办。

**连接 OpenCode**：已加入用户在概览或「成员与接入」查看同一份接入指引。说明「在本地目录通过 CLI 连接，使用账号凭据与工作空间 key；网页不代替你执行命令」。原型只展示带占位符的命令/步骤；可复制示例，不复制真实凭据。创建结果如展示示例 key，要醒目标注「演示、不可用」；日常浏览不输入 workspace token 或 task-key。

**失败和空状态**：登录不匹配、字段缺失、未知空间、邀请不属当前账号、未获权限、空空间/空日志、一次可复现的查询失败。每种状态给简短解释和下一步；清空演示数据用独立的演示入口。待审批及拒绝状态下，即使直接访问内部 URL，也不渲染受限数据。

## 6. Mock 边界、数据和未来接口

- 页面依赖一个统一数据接口而非直接操作夹具或内置 HTTP 常量。操作契约：登录/退出、我的空间与加入状态、创建空间、邀请/接受/申请/审批、概览/日志读取。Mock 以异步结果供页面处理；不绑定生产 URL、请求头或响应形状，不发送网络 API 请求。
- 基础演示数据：一个负责人、一个未加入的申请者、一个可被邀请的独立账号；至少一个已有空间含两个活跃成员、不同状态的团队任务、日志及变更。可另设空空间/空文件夹。全用合成姓名和 `example.test` 邮箱与地址。
- **同一份本机演示状态**供不同身份使用，退出或切换演示身份不重置业务数据。刷新的演示状态可用浏览器存储（只保存合成数据和演示账号 ID），另提供恢复种子数据。原型角色限制在演示数据接口也要生效，不能只隐藏按钮；这不是生产权限或安全隔离。不收集真实密码、token、key，无遥测。
- 每个用户操作只提交一次，等待时不允许重复点击；成功后重新读取受影响状态，失败不留下假成功，重试由用户触发。只模拟单浏览器，跨设备并发、实时连接和真实会话持久化不在范围内。

当前已提交基线的 `/board` 是输入 workspace ID/token 的只读表单。下面是交接时已识别、**必须等用户体验确认后再讨论**的差异：

| 原型交互 | 现有接口/差异 |
|---|---|
| 登录后进空间，无需输入任何 key | `POST /api/auth/login` 是账号凭据；空间读取/管理使用 workspace token，现有 `/api/connect` 需要 task-key。要设计浏览器会话和按成员资格访问的边界，不能直接让页面绕过鉴权或把生产 token 搁在 Mock 存储里。 |
| 我的邀请、申请与拒绝提示 | `GET /api/workspaces` 只列活跃成员的空间；接受/申请写接口与负责人成员列表已存在。成员侧发现邀请/查询自身申请结果没有对应专用列表；审批拒绝在现服务端表示为 `removed`，不是专门的拒绝枚举。 |
| 名称 + 可选参考链接，无分支 | `POST /api/workspaces` 当前要求 1–20 组 `{url,branch}`，不在本轮改服务端接口或迁移数据。 |
| 概览和工程日志目录 | 看板已有成员、任务、变更元数据；正文按路径读取。要验证真实接入用什么已有数据生成当前文件树；不能把最近 50 条变更当全量目录。 |

依据：当前 worktree 的 `server/http/router.ts`、`server/domain/{workspace,membership,access,board}.ts`，以及 `server/README.md`。原型独立启动；回退仅移除原型资源，不改运行中的服务，不需要迁移、灰度或生产日志。

## 7. 给实现 Agent 的顺序与交付验收

1. 先用上述色板、布局和组件在浏览器落出登录/空间列表/概览；确认纯假数据、独立启动。
2. 接 Mock 操作和两种身份，完成创建、邀请接受、申请审批、日志阅读和接入说明；再补状态、键盘和窄屏检查。
3. 给用户一个可打开的本地入口和以下验收路线，**停在体验反馈，不接真接口**。

| 验收 | 通过标准 |
|---|---|
| 负责人建空间并邀请 | 空间显示本人为负责人；已邀请但对方未接受时，对方不能进入；接受后能进入。 |
| 申请审批与拒绝 | A 申请后只能看待审批。负责人通过后 A 可读概览和日志；另一次拒绝后仍无访问权限。重复提交不重复建记录。 |
| 阅读与接入 | 从概览看成员、任务和变化，能定位模拟日志正文；接入说明没有仓库/分支校验或额外确认。任何任务区域都没有写操作。 |
| 状态与隔离 | 演示身份切换保留业务状态；退出、失败重试、直接访问受限页面、空态均可体验；键盘能完成主流程；浏览器只请求本地原型资源，无真实后端或密钥访问。 |
| 用户体验关口 | 用户本人确认页面组织、信息优先级和操作成本后，另开真实接口工作；仓库表单和认证差异届时明确决策。 |
