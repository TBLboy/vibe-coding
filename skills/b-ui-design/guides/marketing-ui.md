# Marketing UI — subject-specific direction

Adapted from Anthropic Frontend Design (Apache-2.0), pinned in `../SOURCES.md`.
This guide does not require fonts, assets, frameworks or external tools.

## Establish the brief

Identify the audience, offering, decision and primary action. A visitor choosing a
service has a different task from an operator using the app. Reuse approved brand
identity and real claims. Do not invent customers, testimonials, revenue, urgency
or credentials. Mark absent client assets as absent; illustrative mock content
must remain explicitly synthetic.

## Plan before code

Propose a compact color/type/spacing system consistent with project constraints,
a one-sentence visual thesis, and a low-fidelity section plan. The opening should
show the most characteristic aspect of the subject, not automatically a huge
headline with stat cards. Compare different composition/narrative choices when
direction is uncertain; three color tints of the same template are not alternatives.

Typography, line measure and imagery express the subject. A system font can be the
right choice; distinctiveness does not require a remote font. Structure, dividers
and numbering must encode real relationships or sequence. Spend visual emphasis
in a few places and keep supporting content quiet. Avoid universal gradients,
glass panels, identical feature cards and repeated decorative labels.

## Copy and interaction

Use concrete, plain copy explaining what is offered and what an action does.
Labels remain consistent through the flow. Place proof near the claim it supports
without fabricating it. Remove repeated claims and CTAs that add no decision value.
Visuals must carry useful product/subject information, not just fill empty space.

Motion can clarify response or an intentional reveal, but must not delay action
or repeat on every section by habit. Preserve reduced-motion, keyboard and mobile
fallbacks. Do not add asset generation, tracking, paid tooling or animation
libraries unless separately authorized. A plan requiring unavailable imagery must
name that gap, not pretend the finished assets exist.

## Review and completion

Review the plan against the actual brief before implementation. Inspect the real
page at narrow, medium and desktop widths, using realistic copy lengths and
actual asset proportions. Check first-viewport offering/action clarity, section
rhythm, contrast, all links/actions, keyboard focus and overflow. If it could be
any unrelated company's page after changing the logo, revisit the subject-specific
structure, not merely the accent color. Report unverified performance or missing
client assets explicitly.
