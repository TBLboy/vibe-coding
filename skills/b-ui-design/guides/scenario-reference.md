# Scenario and style reference — alternatives, not verdicts

Adapted from UI UX Pro Max (MIT), pinned in `../SOURCES.md`. This bundle includes
selected text rules, **not** its searchable CSV datasets, Python engine or CLI.
Do not claim a database search or generated design-system result was run. The
following is a bounded manual selection method, not equivalent coverage of all
upstream industry/platform categories.

## Route by job before style

| Context | Useful direction to evaluate | Invalid shortcut |
|---|---|---|
| Developer/admin workspace | Restrained, dense hierarchy; predictable status and comparison | A terminal costume or cards for every record |
| Collaboration/productivity | Calm shared context, people/task relationships, explicit role/state | Invented online presence or playful movement everywhere |
| Analytics/monitoring | Decision-focused metrics, units, freshness, comparison and drill-down where supported | Decorative chart mosaics or invented live updates |
| Company/brand/service site | Subject-specific typography, real evidence, clear primary action | Copying marketing heroes into the app itself |
| Documentation/reference | Reading measure, headings and wayfinding | A style that replaces document order with a poster |
| Commerce/booking | Clear cost, commitment, progression and recoverable errors | Applying an aesthetic recipe instead of transaction research |
| Mobile Web | Content priority, touch/scroll/keyboard constraints | Treating desktop shrinkage as native mobile design |

## Compare coherent alternatives

For a meaningful direction choice, compare two or three alternatives on one named
axis: density, navigation/reading structure, brand expression or interaction model.
Tie differences to the user job. Preserve existing palette/fonts and constraints
unless replacement is explicitly requested. Industry labels do not mandate dark
mode, glassmorphism, a font pairing, animation or color associations.

## Quality floor

Prioritize accessibility and correct interaction over effects. Use semantic labels,
keyboard/focus support, adequate contrast, non-color state cues and responsive
reflow. Distinguish normative WCAG requirements from recommendations (for example,
44px touch targets are a useful stronger preference, not the universal AA floor).
Validate contrast for actual foreground/background pairs rather than a palette name.
For WCAG 2.2 AA, check text contrast (1.4.3: 4.5:1 normal, 3:1 large text),
non-text contrast (1.4.11), reflow (1.4.10), visible and unobscured focus
(2.4.7, 2.4.11) and target size (2.5.8: 24 CSS px or applicable exception).
These checks have criterion-specific exceptions; verify applicability instead of
using a single pixel rule. Respect reduced-motion preferences for nonessential
motion. Record which criteria and real states were checked; a sample is not a
conformance claim.

Do not add libraries, Google Fonts, remote imagery or charts by default. If a real
decision needs the full upstream searchable catalog, propose that separately with
its license, script inspection and verification scope; lack of that engine does
not justify fabricating results. State the selected evidence and remaining gaps.
